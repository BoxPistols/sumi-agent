# Sumi デザインシステム

Sumi のUIを一貫させ、可読性を保証するための規約。**UIを変更するときは必ずこの文書に従う。**

コンセプトは「和紙と墨」。装飾を足すのではなく、情報の優先順位を色と余白で表現する。

---

## 1. 原則

1. **1画面 = 1目的 = 1つの主アクション。** 主ボタン（塗り）は画面に1つだけ。他はゴースト/アウトラインにする
2. **ユーザーは常に現在地がわかる。** ステップ、進捗、残り件数など「いま何をしていて、あと何が残るか」を必ず表示する
3. **色は意味を持つ。** 装飾目的で新しい色を足さない。役割（下表）に無い色が必要になったら、まず既存の役割で表現できないか検討する
4. **両テーマで検証する。** ライト/ダークのどちらかだけを見て完成としない
5. **コントラストは実測する。** 目視で「読めそう」は根拠にならない。§3 の基準をテストで担保する

---

## 2. カラートークン

色は CSS Custom Properties 経由で参照する。`RedactPro.tsx` の `T` オブジェクトが参照ラッパー、`C` がハードコード定数。

### 2.1 基盤（テーマで反転する）

| トークン       | 役割                         | ライト            | ダーク              |
| -------------- | ---------------------------- | ----------------- | ------------------- |
| `T.bg`         | ページ背景                   | `#FAF9F6`（和紙） | `#1C1917`（墨）     |
| `T.bg2`        | ヘッダー・フッター・バー背景 | `#FFFFFF`         | `#292524`           |
| `T.surface`    | カード・パネル面             | `#FFFFFF`         | `#292524`           |
| `T.surfaceAlt` | 面の上の面（バッジ等）       | `#F5F5F4`         | `#44403C`           |
| `T.border`     | 境界線                       | `#E7E5E4`         | `#44403C`           |
| `T.text`       | 本文                         | `#1C1917`         | `#E7E5E4`           |
| `T.text2`      | 補足テキスト                 | `#57534E`         | `#A8A29E`           |
| `T.text3`      | 非活性・ヒント               | `#A8A29E`         | `#78716C`           |
| `T.accent`     | 主アクション・現在地         | `#1C1917`（墨黒） | `#E7E5E4`（和紙白） |

**重要:** `T.accent` はテーマで反転する。塗りボタンの文字色は必ず `T.bg` を使う（`#fff` 固定にするとダークテーマで消える）。

### 2.2 意味色（テーマで反転しない）

| トークン   | 意味                                         | 値        |
| ---------- | -------------------------------------------- | --------- |
| `C.stamp`  | ロゴの朱印**のみ**。UIアクセントには使わない | `#DC2626` |
| `C.red`    | 氏名カテゴリ・危険・削除                     | `#DC2626` |
| `C.green`  | 完了・保護中・成功                           | `#059669` |
| `C.amber`  | 警告・注意・要確認                           | `#D97706` |
| `C.purple` | AI関連機能                                   | `#9B6DFF` |
| `C.cyan`   | URL・リンク系                                | `#22D3EE` |

各色には `〜Dim`（10%程度の背景色）が対になっている。**文字色に意味色、背景に対応する Dim** を組み合わせるのが基本形。

### 2.3 意味色を「背景」に使うときの注意

`C.purple` `C.cyan` `C.green` などの明るい意味色を**塗りの背景**にすると、白文字でもコントラストが不足しやすい。塗りに使うときは暗いトーンを選ぶ。

| 用途             | 使う値                      | 白文字とのコントラスト |
| ---------------- | --------------------------- | ---------------------- |
| 紫の塗りボタン   | `#7c3aed` 〜 `#6d28d9`      | 5.70:1 / 7.10:1 ✅     |
| 使ってはいけない | `#a78bfa`                   | 2.72:1 ❌              |
| 使ってはいけない | `#9B6DFF`（塗り背景として） | 3.49:1 ⚠️ 本文には不足 |

`#9B6DFF` は**文字色・アイコン色・境界線**として使う色であり、塗り背景ではない。

## 3. コントラスト基準

| 対象                                             | 最低比               |
| ------------------------------------------------ | -------------------- |
| 本文・ボタン内テキスト                           | **4.5:1**（WCAG AA） |
| 大きな文字（18px以上 or 14px太字以上）・UIの境界 | **3:1**              |
| 装飾のみの要素（罫線、影）                       | 基準なし             |

- 既存テスト `src/lib/__tests__/a11y-contrast.test.ts` が主要な組み合わせを検証している。**新しい色の組み合わせを追加したらテストにも追加する**
- グラデーションは**両端**で基準を満たすこと。片方だけ合格は不可

## 4. タイポグラフィ

| 用途             | サイズ  | ウェイト                                   |
| ---------------- | ------- | ------------------------------------------ |
| 画面見出し       | 22–24px | 700                                        |
| セクション見出し | 15–16px | 700                                        |
| 本文             | 13–14px | 400                                        |
| ラベル・ボタン   | 12–13px | 500–600                                    |
| 補足・ヒント     | 11–12px | 400                                        |
| カウンター・数値 | 11–13px | 600 + `font-variant-numeric: tabular-nums` |

- フォント: `T.font`（Noto Sans JP / DM Sans）、等幅は `T.mono`
- 行間: 本文 1.7、UIラベル 1.4
- 数字が変化し続ける表示（`7 / 12`、経過時間、件数）は `tabular-nums` で桁を固定し、ガタつかせない

---

## 5. スペーシングと角丸

- 間隔は **4px 基準**（4 / 8 / 12 / 16 / 20 / 24 / 32）
- 角丸: バッジ 4–6px / ボタン・入力 8–10px / カード・モーダル 12px / 円形は 50%
- 画面端の余白: デスクトップ 32–40px、モバイル 10–16px

## 6. コンポーネント規約

### ボタン階層

| 階層    | 見た目                                                | 使いどころ                     |
| ------- | ----------------------------------------------------- | ------------------------------ |
| Primary | `background: T.accent` + `color: T.bg`                | その画面で次にすべき唯一の操作 |
| Outline | 透明背景 + `1.5px solid T.accent` + `color: T.accent` | 補助的だが重要な操作           |
| Ghost   | 背景・枠なし + `color: T.text2`                       | 戻る、キャンセル、副次操作     |

**1画面に Primary は1つ。** 2つ以上並べたくなったら、それは画面を分けるべきサイン。

### アクセシブルネーム

- 共通 `Btn` は `aria-label` 未指定時に `title` をアクセシブルネームに使う。**可視テキストを持つボタンには可視テキストと同じ `aria-label` を明示する**（WCAG「label in name」。e2eのrole検索も安定する）
- アイコンのみのボタンは `title` と `aria-label` の両方を必ず付ける

### 状態表示

- 進行中: 進捗バー + パーセント + 現在の工程名 + 経過時間
- ステップ型UI: **必ず「現在地 / 全体数」を数字で示す**（`7 / 12`）。進捗バーだけでは残量が読めない
- 空・エラー: 何が起きたか + 次にできることを1文で

### モーダル・オーバーレイ

- `role="dialog"` + `aria-modal="true"` + `aria-label`
- Esc で閉じる、閉じたらトリガー要素へフォーカスを戻す
- 背後の要素と同じアクセシブルネームのボタンを置かない（テストが曖昧になる）

## 7. テーマ実装ルール

1. 色は必ず `T.*`（CSS変数）経由。CSSファイルでは `var(--rp-*)` を使う
2. `#fff` / `#000` の直書きは、**両テーマで固定してよいと確認できた場合のみ**（例: 暗い塗り背景の上の白文字）
3. `[data-theme='light']` の上書きを書くときは**詳細度の順序に注意する**。
   `[data-theme='light'] .foo`（0,2,0）は `.foo-primary`（0,1,0）に勝つ。プライマリ系の上書きは、必ずベース規則より後ろに同等以上の詳細度で書く
   （実例: intro.js の「次へ」ボタンがライトテーマで紫地に黒文字 1.79:1 になった不具合）
4. `currentcolor` は小文字（Stylelint `value-keyword-case`）

## 8. UI変更時のチェックリスト

- [ ] この画面の主アクションは1つか
- [ ] 現在地・進捗（`n / N`）がわかるか
- [ ] 新しい色を足していないか。足したなら役割表に追記したか
- [ ] 文字と背景のコントラストは 4.5:1 以上か（グラデーションは両端）
- [ ] ライト/ダークの両方で確認したか
- [ ] 可視テキストと `aria-label` が一致しているか
- [ ] `pnpm build` / `pnpm test` / `pnpm lint` / `pnpm type-check` が通るか
- [ ] `pnpm test:e2e`（UI構造を変えた場合）

## 9. AIプロバイダ表示

対応プロバイダは **OpenAI（GPT-5.6 Luna） / Gemini / ローカルAI** の3つのみ。定義は `src/lib/constants.ts` の `AI_PROVIDERS` が単一の情報源。

- プロバイダ選択ボタンは `--provider-color` にブランド色を渡し、選択中のみ着色する
- APIキーが必要なプロバイダは「要APIキー」を明示する
- 設定画面には**接続テスト**を必ず用意する。ローカルAIは入力中のエンドポイントをそのまま検証し、失敗時は原因（未起動 / エンドポイント誤り）まで示す
- モデルを増減したら `src/lib/__tests__/model-lineup.test.ts` を更新する
